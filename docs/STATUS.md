# 当前状态

更新时间：2026-10-03

## 当前阶段

正式接口契约与三端低保真前端原型已完成，可用于业务演示及后续前后端联调。当前未创建后端工程、数据库表或迁移脚本；下一阶段按现有契约实现 Java 模块化单体后端。

## 已完成

- `docs/api/openapi.yaml` 已成为唯一正式接口契约，采用 OpenAPI 3.0.3，包含 75 个 HTTP 操作、125 个 Schema，覆盖客户、服务人员和管理员。
- 契约明确 JWT Bearer、角色与资源权限、统一响应、分页、DTO/VO/Query、业务状态、字符串错误码、幂等请求头、字符串 ID、两位小数字符串金额、北京时间和报价版本冲突；同文件定义 `/ws` 的认证首帧、公共事件结构、事件类型、载荷及重连重查规则。
- `home-service-web` 为独立 Vue 3 + Vite + TypeScript + npm 工程，采用 `api`、`views/{customer,worker,admin,shared}`、`layouts`、`router`、`components`、`composables`、`stores`、`mock` 分层。参考苍穹前端的业务模块和集中请求组织，不继承 Vue 2、旧 token 头或旧响应格式。
- TypeScript 类型、请求路由元数据和 Mock 校验 Schema 由 OpenAPI 生成；`api:check` 检查语法、引用和生成结果一致性，Mock 输入与成功响应执行 Schema 校验。
- 客户端实现注册登录、目录筛选分页、地址维护、预约、模拟支付、报价加减、补差和退款、订单查询、取消、开始码查看、确认完成与一次性评价。
- 服务人员端实现排班模板、固定休息日、请假及撤销、未来30天时间槽、优惠抢单和完整履约操作；开始码由客户提供，不在人员查询中泄漏。
- 管理端实现账号、人员技能与派单开关、分类/项目/SKU/价格/上下架、技能、平台配置、订单异常取消、支付退款流水、调度尝试及审计查询。不存在手工派单或改派。
- Mock 支持跨标签页共享业务数据、独立登录、条件匹配、服务及尾部缓冲占用、报价版本校验、幂等重放、退款审计和在线通知。演示工具支持时间推进、到期任务、网络故障和重置。
- 两种请求模式复用同一契约与页面。默认 Mock；设置 `VITE_USE_MOCK=false` 后使用真实同源 `/api` 和 `/ws`，开发代理目标可由未提交的本机环境文件配置，源码不硬编码后端地址。
- 页面保持黑白低保真，表单、导航、空列表、筛选、分页、滚动、状态和异常提示可操作；桌面和移动视口已检查。

## 已落实的接口细节

- 主履约、支付、调度、分配分别定义状态；失败调度尝试不会伪装成分配记录。
- 优惠报价以最低价为锚点按5元步进，低于标准价；调价和抢单均带预期金额与 `priceVersion`。旧版本失败后需重新查询并由用户确认。
- 服务项目 `serviceKind` 表达清洁、维修或其他业务性质，与可维护分类的名称/ID分离；当前只有清洁可开放优惠，不写死分类ID。
- 时间槽和缓冲须完整位于工作区间；缩短排班、新增休息日或请假不得破坏已有分配。当前原型用可计算的槽视图模拟，后端仍须按 PROJECT.md 实现预生成槽与事务条件更新。
- 客户取消仅允许待支付、待派单、待抢单和待服务；管理员异常取消必须有原因。退款按净收款生成流水，用户操作和系统到期任务分别记录审计操作者类型。
- `/ws` 在连接后使用 AUTH 首帧提交访问令牌，认证前不推送业务数据；URL 不携带令牌。确认中的报价快照不会被通知静默替换。
- 目录删除在 Mock 中保留归档实体与审计；订单、流水、报价及分配历史保留。

## 运行与验证

在 `home-service-web` 内使用 Node.js 22.12+：

```sh
npm install
npm run dev
npm run build
npm run api:check
npm run format:check
npm test
npx playwright install chromium
npm run test:e2e
```

- 三端入口：`/customer/login`、`/worker/login`、`/admin/login`。
- 演示账号：客户 `customer` / `customer2`；人员 `worker` / `worker2` / `repair`；管理员 `admin`。演示密码统一 `Demo12345`，全部数据虚构。
- 契约语法、引用、示例及生成一致性检查通过。
- TypeScript 严格检查、Vite 生产构建和 Prettier 格式检查通过。
- 26 项业务测试通过：权限、幂等、金额、分页、报价版本、并发抢单结果、时间槽竞争、排班请假、超时退款、履约评价、目录引用与归档、人员维护、地址快照、配置和退款审计。
- 6 项 Chromium 浏览器场景通过：注册及地址维护；标准预约至评价；跨标签页报价冲突与竞争抢单；后台价格维护与异常取消退款；排班请假与断网反馈；真实 fetch 分支的同源路径、认证、WebSocket首帧、支付响应丢失后的幂等重试和登录过期。
- 真实 fetch 分支使用测试拦截器验证协议，尚未连接真实 Java 后端。Mock 使用 Web Locks 串行化浏览器写操作，不能替代后续 MySQL 并发与事务测试。
- `node_modules`、`dist`、浏览器测试结果及本机环境文件均由 Git 忽略；仅创建本地提交，未推送远端。
