# 当前状态

更新时间：2026-10-04

## 当前阶段

三端低保真原型与正式接口契约已完成。客户端预约、报价和返回流程已完善，服务人员端已重构为竖屏任务与抢单流程，可用于产品演示和后续前后端联调。当前没有创建后端工程、数据库表或迁移脚本。浏览器 Mock 成功仅代表原型模拟，不代表真实后端已实现。

## 已完成

- `docs/api/openapi.yaml` 是唯一正式接口契约，采用 OpenAPI 3.0.3，包含85个 HTTP 操作、143个 Schema。沿用三端前缀、JWT Bearer、统一响应、分页、DTO/VO/Query、字符串错误码、幂等键、字符串 ID、两位小数字符串金额、Asia/Shanghai 时间和报价版本冲突规则；同文件定义 `/ws` 认证首帧及通知事件。已补充报价规则快照、人员电话编辑、完整统计、月历合并区间、排序、技能名称及排班冲突订单引用。
- `home-service-web` 保持 Vue 3 + Vite + TypeScript + npm 独立标准工程。类型、路由元数据和 Mock 校验 Schema 从契约生成。默认 Mock，`VITE_USE_MOCK=false` 切换真实同源 `/api` 与 `/ws`，不硬编码本机后端地址。
- 客户端与人员端共用随视口变化的竖屏布局：桌面根据高度和9:16比例居中，窄屏适配实际宽度；标题、一级导航或主要操作栏稳定，中间独立滚动。使用 VisualViewport 可用高度处理视口缩短，弹窗正文可滚动、提交栏可到达，不制作固定尺寸手机外壳。
- 一级导航为首页、订单、我的。首页固定清洁与维修入口；清洁选择弹窗、日常/深度切换、固定套餐、简短详情和维修三组选择均可操作。未登录可浏览，预约与个人业务需要登录并回到原操作。
- 固定入口通过 `clientEntryCode` 显式绑定正式 SKU，后台维护价格、时长、优惠能力和上下架；入口缺失、下架或性质不匹配时不可预约，不按目录名称或列表顺序猜测，不因新增后台分类自动增加入口。管理员规格编辑中可维护绑定。
- 预约面板支持默认/切换/新增地址并返回、独立本次联系人、日期与半小时时间选择、结束时间、备注、现场图片与草稿恢复。默认地址唯一，删除默认地址后选择最早添加的剩余地址。
- 初始报价与订单调价共用报价组件和校验。新订单报价为5元整数倍，不低于最低价且严格低于标准价；最低价向上取合法报价，建议价取价格中点向下对齐后限制在合法区间，无合法值时禁止优惠。历史订单保留原最低价锚点规则快照，不随目录变更。非法输入不静默修正，边界按钮禁用；不足12小时由客户明确选择改为标准预约，维修仅标准预约。
- 订单卡片和详情提供独立调价弹窗，展示原价、范围、差额、补付或退款；无变化不可提交，加价明确确认模拟补付。冲突保留原报价并展示最新报价，查看和重新确认后才能继续；来源状态、截止、幂等和版本校验继续由契约与 Mock 校验。
- 创建订单后进入独立模拟支付确认页，未支付退出到订单详情并保留15分钟期限。创建订单和支付幂等键在同一标签页刷新后仍可用于重试；支付成功进入结果页，展示安排、等待、取消退款或优惠接单结果，返回首页并提供查看订单进度。支付结果不确定时持续提示并允许查询或同键重试。
- 客户订单使用卡片与浏览分组，正式状态保持独立；详情包含人员、履约、开始码、本次联系人、地址、备注、图片、支付退款及报价历史，保留来源状态校验、锁价、取消限制、确认完成和一次性评价。通知不静默替换正在确认的报价。
- 我的页面支持个人称呼、联系电话编辑，用户名只读；个人资料、地址簿联系人和订单本次联系人分离。三端独立登录入口保留，演示工具移至独立开发页面，正常客户业务导航不展示切换端入口。
- 三端共用内容顶部错误浮层，普通错误2秒消失且不堆叠，弹窗打开时仍可见。前端在失焦或提交时校验；字段错误保留到修正，接口字段错误能定位输入项。报价冲突、网络结果不确定及排班冲突保留必要的持续说明。
- 返回遵守业务层级：清洁切换不增加历史层级，维修逐级返回，预约及地址操作保留草稿；底部导航替换当前一级记录。订单详情返回原列表或任务入口，恢复筛选和内部滚动；直接链接有兜底。没有全局拦截浏览器返回。
- 管理员端保留原有目录、账号、人员、配置、异常取消、支付退款、调度和审计功能，仅补充共用错误展示与字段定位；不增加手工派单。

## 服务人员端

- 一级导航为首页、订单、我的，正常流程不展示跨角色切换。首页上方为优先任务及下一单摘要，全部任务在接近全屏的面板展开，关闭恢复抢单池位置。标准分配和自主抢单统一进入任务，保留来源，无额外接受/拒绝步骤。
- 抢单池按完整资格过滤后排序再分页；默认截止时间升序、发布时间升序、数值ID升序，可切换最新发布。新增订单仅提示数量，主动刷新后加入；已有报价变化、被接走、到期或资格变化明确反馈。确认窗口保留原价格，HTTP决定最终结果。通知断开显示状态，重连重新同步；不声称支持手机后台推送。
- 订单使用卡片及准确状态分组，完整排序后分页：进行中、待服务、待确认、历史；历史按实际关闭时间倒序。顺序履约、客户提供开始码、待客户确认与24小时自动完成规则保留，人员无法自行取消或改价。
- 我的包含资料、服务数据、工作时间与请假、服务规则和退出。姓名、账号、技能名称、城市、状态与调度资格只读；联系电话可通过正式接口修改。
- 统计使用独立完整聚合接口。北京时间今日待服务按预约日期与待服务状态；本月及累计完成按实际完成确认时间 `closedAt`，不含待客户确认。时长仅为已完成订单的预约服务时长，订单金额不视为收入，不增加结算。
- 月历展示未来30天与所选月份交集，区分未设置、休息、工作时间内空闲、有安排和请假。选中日期展示合并后的服务、服务后预留间隔、请假及可接区间；缓冲不算空闲，剩余空闲不保证容纳任意服务。沿用统一工作区间和每周休息日，不增加逐日排班或扩大预约窗口。
- 请假仍要求半小时粒度、提前2小时，并校验服务和缓冲冲突；冲突可打开对应本人订单，返回保留日历选择和草稿。保存后刷新安排，进入首页重新查询接单资格；无自行上下线开关。

## 图片与权限

- 客户可选上传至多3张 JPEG/PNG/WebP 图片，单张最多5 MiB、解码后最多4000万像素；页面支持选择、预览、移除、类型/大小/数量限制和失败重试。上传前重编码清理照片元数据，提示避开个人隐私；图片不保证接单、不扩大服务范围、不允许现场议价。
- 契约定义 multipart 上传、临时图片删除与三端鉴权内容读取。图片内容成功响应为二进制流，是统一 JSON 响应的明确例外；错误仍使用统一响应，要求私有且不缓存。不存在公开图片列表或公开文件 URL。
- 客户仅可读取本人图片；人员和管理员必须提供图片所属订单 ID。人员仅在已分配给本人，或待抢单且当前符合资格时可访问；抢单前不提供结构化联系人、电话、门牌或开始码。管理员按订单关联查看。每次读取重新判权。
- 订单保存不可变图片关联；已关联历史订单的图片不能作为临时附件删除。地址和目录编辑不修改历史联系人、服务或图片快照。
- Mock 图片内容保存在 IndexedDB，业务引用与其他演示数据保存在 localStorage；查看通过同一请求层判权后生成临时对象 URL，离页撤销。真实模式需要后端实现独立的图片内容验证、元数据清理、存储与授权，当前没有上传后端工程。

在 `home-service-web` 内使用 Node.js 22.12+：

```sh
npm install
npm run dev
npm run build
npm run api:check
npm run format:check
npm test
npx playwright install chromium
npm run test:e2e
```

- OpenAPI 语法、引用、示例和生成结果一致性检查通过；Prettier、TypeScript 严格检查、Vite 生产构建通过。
- 38项业务测试通过，覆盖权限、幂等、抢单竞争、退款履约、图片隐私、预约边界，以及新旧报价规则、非5元倍数最低价、空报价区间、历史快照、分页前排序、完整统计、电话编辑权限、月历休息/未设置/合并区间和缓冲请假冲突。
