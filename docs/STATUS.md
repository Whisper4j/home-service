# 当前状态

更新时间：2026-10-03

## 当前阶段

三端低保真原型与正式接口契约已完成，客户端已改为竖屏预约流程，可用于产品演示和后续前后端联调。当前没有创建后端工程、数据库表或迁移脚本。浏览器 Mock 成功仅代表原型模拟，不代表真实后端已实现。

## 已完成

- `docs/api/openapi.yaml` 是唯一正式接口契约，采用 OpenAPI 3.0.3，包含82个 HTTP 操作、133个 Schema。沿用三端前缀、JWT Bearer、统一响应、分页、DTO/VO/Query、字符串错误码、幂等键、字符串 ID、两位小数字符串金额、Asia/Shanghai 时间和报价版本冲突规则；同文件定义 `/ws` 认证首帧及通知事件。
- `home-service-web` 保持 Vue 3 + Vite + TypeScript + npm 独立标准工程。类型、路由元数据和 Mock 校验 Schema 从契约生成。默认 Mock，`VITE_USE_MOCK=false` 切换真实同源 `/api` 与 `/ws`，不硬编码本机后端地址。
- 客户端为随视口变化的竖屏布局：桌面根据可用高度和9:16比例居中，窄屏适配实际宽度；标题、一级导航或主要操作栏稳定，中间独立滚动。使用 VisualViewport 可用高度响应键盘等造成的视口缩短，不制作固定尺寸手机外壳。
- 一级导航为首页、订单、我的。首页固定清洁与维修入口；清洁选择弹窗、日常/深度切换、固定套餐、简短详情和维修三组选择均可操作。未登录可浏览，预约与个人业务需要登录并回到原操作。
- 固定入口通过 `clientEntryCode` 显式绑定正式 SKU，后台维护价格、时长、优惠能力和上下架；入口缺失、下架或性质不匹配时不可预约，不按目录名称或列表顺序猜测，不因新增后台分类自动增加入口。管理员规格编辑中可维护绑定。
- 预约面板支持默认/切换/新增地址并返回、独立本次联系人、日期与半小时时间选择、结束时间、备注、现场图片与草稿恢复。默认地址唯一，删除默认地址后选择最早添加的剩余地址。
- 优惠预约显示标准价、最低价、建议价与当前报价，建议价为价格中点向下对齐5元步长，支持按钮及手动调整；不足12小时明确提示并由客户主动选择标准预约。维修仅显示标准预约。
- 创建订单后进入独立模拟支付确认页，未支付可退出并保留15分钟期限。创建订单和支付幂等键在同一标签页刷新后仍可用于重试；支付后展示自动安排、重试等待、超时取消退款或优惠等待接单。
- 客户订单使用卡片与浏览分组，正式状态保持独立；详情包含人员、履约、开始码、本次联系人、地址、备注、图片、支付退款及报价历史，保留来源状态校验、锁价、取消限制、确认完成和一次性评价。通知不静默替换正在确认的报价。
- 我的页面支持个人称呼、联系电话编辑，用户名只读；个人资料、地址簿联系人和订单本次联系人分离。三端独立登录入口保留，演示工具移至独立开发页面，正常客户业务导航不展示切换端入口。
- 服务人员端和管理员端保留原有业务闭环，只补充订单本次联系人与现场图片查看，以及必要的入口绑定维护。人员排班、请假、抢单和顺序履约；管理员目录、账号、人员、配置、异常取消、调度和审计仍可操作，不增加手工派单。

## 图片与权限

- 客户可选上传至多3张 JPEG/PNG/WebP 图片，单张最多5 MiB、解码后最多4000万像素；页面支持选择、预览、移除、类型/大小/数量限制和失败重试。上传前重编码清理照片元数据，提示避开个人隐私；图片不保证接单、不扩大服务范围、不允许现场议价。
- 契约定义 multipart 上传、临时图片删除与三端鉴权内容读取。图片内容成功响应为二进制流，是统一 JSON 响应的明确例外；错误仍使用统一响应，要求私有且不缓存。不存在公开图片列表或公开文件 URL。
- 客户仅可读取本人图片；人员和管理员必须提供图片所属订单 ID。人员仅在已分配给本人，或待抢单且当前符合资格时可访问；抢单前不提供结构化联系人、电话、门牌或开始码。管理员按订单关联查看。每次读取重新判权。
- 订单保存不可变图片关联；已关联历史订单的图片不能作为临时附件删除。地址和目录编辑不修改历史联系人、服务或图片快照。
- Mock 图片内容保存在 IndexedDB，业务引用与其他演示数据保存在 localStorage；查看通过同一请求层判权后生成临时对象 URL，离页撤销。真实模式需要后端实现独立的图片内容验证、元数据清理、存储与授权，当前没有上传后端工程。

## 运行与验证

在 `home-service-web` 内使用 Node.js 22.12+：

```sh
npm install
npm run dev
npm run build
npm run api:check
npm run format:check
npm test
npx playwright install chromium
npm run test:e2e
```

- 客户首页：`/customer/home`；独立登录：`/customer/login`、`/worker/login`、`/admin/login`。Mock 客户演示工具在“我的 → 关于产品原型 → 打开独立演示工具”，路径 `/customer/development`。
- 虚构演示账号：客户 `customer` / `customer2`，人员 `worker` / `worker2` / `repair`，管理员 `admin`；演示密码统一 `Demo12345`。
- OpenAPI 语法、引用、示例和生成结果一致性检查通过；Prettier、TypeScript 严格检查、Vite 生产构建通过。
- 32项业务测试通过，覆盖原有权限、幂等、抢单竞争、排班请假、时间槽、退款与履约，以及固定入口绑定、资料/联系人分离、图片所有权和动态资格、文件限制、默认地址、多状态查询、优惠金额与预约时间边界。
- 11个 Chromium 浏览器场景通过，实际点击验证公开入口与登录回跳、清洁/维修选择、地址新增返回、个人资料、三张图片选择/预览/删除/重试/保存及三端查看、报价限制与冲突、订单分组分页、支付安排和超时退款、开始码/履约/确认/评价、后台维护、断网与登录过期。
- 响应式场景覆盖1440×1000、1200×800、360×640、320×480及360×500；聚焦表单后缩短至360×300，检查内部滚动、无横向溢出和底部提交栏可见。已查看小屏详情与订单截图；未以此声称在实体手机上测试过软键盘。
- 真实 fetch 分支通过 HTTP 拦截器验证 `/api` 同源请求、Bearer、multipart 图片上传、鉴权图片流、创建/支付响应丢失后的同键重试、`/ws` 认证首帧和登录过期。尚未连接真实 Java 后端。
- Mock 使用 Web Locks 串行化多标签页写操作并模拟到期任务，不能替代后续 MySQL 事务、条件更新与并发验证。`node_modules`、`dist`、测试结果及本机配置均不提交；仅创建本地提交，未推送远端。
